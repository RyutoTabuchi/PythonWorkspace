# Tests

このフォルダには、自動テスト、試作、調査、手動確認用のコードを配置します。

自動テストと試作コードを混在させず、必要に応じて次のサブフォルダへ分けてください。

```text
tests/
├─ automated/
└─ experiments/
```

## automated

`automated/` には、正式な処理を繰り返し検証する自動テストを配置します。

主な用途は次のとおりです。

- 期待した戻り値になることの確認
- 不正な入力が正しく拒否されることの確認
- 修正後に以前の機能が壊れていないことの確認
- 不具合修正後の再発防止
- 同じ条件で繰り返し実行できる確認

ルールは次のとおりです。

- テスト対象は原則として `source/` 内の正式なコードとします。
- 期待結果を明確にしてください。
- 同じ条件で繰り返し実行できるようにしてください。
- テストファイルは原則として `test_*.py` 形式とします。
- 実業務データは使用しないでください。

## experiments

`experiments/` には、本番採用前の試作、調査、手動確認用コードを配置します。

主な用途は次のとおりです。

- 実装方法の比較
- Python標準機能の挙動確認
- 許可済みライブラリの動作確認
- 一時的な調査
- 実験的な変換処理
- 期待結果がまだ完全に決まっていない確認

ルールは次のとおりです。

- pytestに誤って収集されないよう、ファイル名へ `test_` を付けないでください。
- 正式な本番コードから `tests/experiments/` をimportしないでください。
- 継続して使用する処理は `source/` へ移してください。
- 再現可能な確認として残す場合は `tests/automated/` へ移してください。
- 旧コードの恒久保管場所として使用しないでください。
- 不要になった試作コードは削除してください。
- 実業務データ、個人情報、機密情報、認証情報を置かないでください。

## 外部パッケージ

自動テストまたは試作だけで使用する外部パッケージは、`requirements-dev.txt` で管理します。

本番処理でも必要になったパッケージは、用途を確認したうえで `requirements.txt` へ移してください。

外部パッケージは、実行用か開発用かにかかわらず、ワークスペース共通の許可リストへ登録する必要があります。

パッケージを直接 `pip install` せず、ワークスペース共通の導入ツールを使用してください。

## データの扱い

次の情報を `tests/` へ保存しないでください。

- 実業務データ
- 個人情報
- 機密情報
- 認証情報
- APIキー
- パスワード
- アクセストークン
- 顧客情報

テストデータが必要な場合は、実データを匿名化したように見せかけるのではなく、用途に合わせて安全な検証用データを作成してください。
